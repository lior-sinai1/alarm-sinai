# alarm-sinai-hub

גשר עצמאי בין חיישן ה-TUYA (Wi-Fi, PIR + אור/חום/לחות בדגם "With TH") לבין
Fibaro Home Center.

זהו תהליך (process) נפרד לגמרי מ-`server.js` ומאפליקציית האנדרואיד. הוא לא כותב
לשום קובץ שהאפליקציה קוראת ממנו (`/status` וכו'), ולכן החיישן **לא יופיע באפליקציה** —
בכוונה. תפקידו היחיד הוא לקרוא מהחיישן את מצב התנועה, ואם קיימים — גם עוצמת
אור, טמפרטורה ולחות, ולעדכן משתנים גלובליים ב-Fibaro, כדי שתוכל לבנות Scene
ב-Fibaro שמגיב לזה.

## איך זה עובד

```
חיישן Tuya (רשת מקומית, WI-FI) --local key--> hub (Node/TS) --REST API--> Fibaro Home Center
```

התקשורת עם החיישן היא **מקומית בלבד** (LAN, פרוטוקול Tuya Local) — לא דרך ענן Tuya.
זה דורש חילוץ חד-פעמי של `deviceId` ו-`localKey` (ראה שלב 2).

## שלב 1: התקנה וצימוד החיישן

1. הורד את אפליקציית "Smart Life" או "Tuya Smart" והוסף את החיישן (Wi-Fi 2.4GHz בלבד).
2. ודא שהחיישן מקבל IP קבוע ברשת (מומלץ Reservation ב-DHCP של הראוטר).

## שלב 2: חילוץ deviceId ו-localKey

זה השלב היחיד שדורש חשבון Tuya IoT (חינמי). האפליקציה עצמה לא חושפת את המפתח,
לכן צריך כלי חילוץ:

```bash
npx --package=@tuyapi/cli tuya-cli wizard
```

הכלי ידריך אותך ליצור פרויקט חינמי ב-https://iot.tuya.com, לקשר את חשבון
Smart Life שלך, ובסוף יציג רשימת מכשירים עם `id` ו-`key` לכל אחד. מצא את
החיישן שלך ברשימה ושמור את שני הערכים.

## שלב 3: קונפיגורציה

```bash
cd hub
cp config.example.json config.json
```

ערוך את `config.json`:

```jsonc
{
  "tuya": {
    "deviceId": "...",       // מהשלב הקודם
    "localKey": "...",       // מהשלב הקודם
    "ip": "",                 // ריק = גילוי אוטומטי ברשת; אפשר לקבע ל-IP הסטטי
    "version": "3.3",         // רוב חיישני ה-PIR האלה הם 3.3; אם אין חיבור נסה "3.4"
    "motionDpId": "1",         // מזהה ה-datapoint של תנועה; ברוב הדגמים זה "1"

    // שלושת אלה אופציונליים — רק בדגם "With TH" (עם חיישן אור/חום/לחות).
    // אם אין לך אותם, פשוט מחק את הזוג המתאים גם כאן וגם ב-fibaro למטה.
    "illuminanceDpId": "101",  // מזהה ה-DP של חיישן האור (עוצמת תאורה, lux)
    "illuminanceScale": 1,
    "temperatureDpId": "102",  // מזהה ה-DP של חיישן החום
    "temperatureScale": 0.1,   // Tuya שולח טמפרטורה כמספר שלם פי 10 (23.5° = 235)
    "humidityDpId": "103",     // מזהה ה-DP של חיישן הלחות
    "humidityScale": 1
  },
  "fibaro": {
    "host": "192.168.1.X",             // IP של ה-Home Center ברשת המקומית
    "username": "...",                  // משתמש עם הרשאת API ב-Fibaro
    "password": "...",
    "globalVariableName": "TuyaMotion", // משתנה גלובלי לתנועה (חובה)

    // משתנים גלובליים לערוצים האופציונליים — כל אחד נדרש רק אם ה-DP המתאים
    // מוגדר למעלה (למשל אם אין illuminanceDpId, אפשר למחוק גם את זה)
    "illuminanceVariableName": "TuyaLux",
    "temperatureVariableName": "TuyaTemp",
    "humidityVariableName": "TuyaHumidity"
  }
}
```

`config.json` נמצא ב-`.gitignore` ולא ייכנס ל-git (בדיוק כמו
`firebase-service-account.json` בפרויקט הראשי).

> מזהי ה-DP (`motionDpId`, `illuminanceDpId` וכו') משתנים בין דגמים ומהדורות
> קושחה, אז הערכים למעלה הם רק ברירת מחדל סבירה. ריצה עם `npm run dev` תדפיס
> לוג עם כל ה-DPs שמתקבלים מהחיישן בכל שינוי (`payload.dps`); הניפו יד מול
> החיישן, כסו/גלו אותו מאור, ונשמו עליו — ותראו איזה מזהה זז ולאיזה כיוון,
> ותוכלו להתאים את המספרים בקונפיג בהתאם.

## שלב 4: הגדרה ב-Fibaro

אין צורך ליצור את המשתנים הגלובליים מראש — הגשר יוצר אוטומטית בהרצה הראשונה
כל משתנה שהגדרת בקונפיג ועדיין לא קיים ב-Fibaro.

- `TuyaMotion` (0/1) — הצתת מערכת האבטחה, הדלקת תאורה וכו׳.
- `TuyaLux`, `TuyaTemp`, `TuyaHumidity` — כל ערך מספרי (טקסט) שמתעדכן בכל שינוי;
  אפשר להשתמש בהם לאוטומציה לפי תנאי סביבה (למשל לכבות אורות רק אם גם חשוך
  וגם אין תנועה).

הקובץ [`fibaro/TuyaMotionScene.lua`](fibaro/TuyaMotionScene.lua) הוא Scene מוכן
שרץ אוטומטית בכל שינוי ב-`TuyaMotion`. להתקנה:

1. ב-Fibaro: **Panels → Scenes → Add scene → Lua**.
2. הדבק את תוכן הקובץ.
3. פתח את הפעולה הרצויה בקוד (Push, הדלקת מכשיר, Home Security וכו') —
   כל האפשרויות מגיעות כהערות מבוטלות (`--`), פשוט הסר את ה-`--` מהשורות
   שרלוונטיות לך והחלף את ה-ID-ים לדוגמה ב-ID האמיתיים של המכשירים שלך.
4. שמור והפעל את ה-Scene.

הבלוק `%% globals TuyaMotion` בראש הקובץ גורם ל-Scene לרוץ אוטומטית בכל עדכון
של המשתנה (אין צורך גם להגדיר טריגר ידנית ב-GUI, אבל אפשר בנוסף אם תרצה).

### אופציה נוספת: Virtual Device במקום/בנוסף ל-Scene

אם אתה רוצה שהחיישן יופיע כ**מכשיר** אמיתי בפאנל של Fibaro (ולא רק כמשתנה
גלובלי) — [`fibaro/TuyaMotionVirtualDevice.lua`](fibaro/TuyaMotionVirtualDevice.lua)
הוא קוד ל-Main Loop של Virtual Device שקורא את אותם משתנים גלובליים ומציג
אותם. **אין צורך בשום שינוי בגשר** — זו רק תצוגה נוספת מעל אותם נתונים.

התקנה:

1. ב-Fibaro: **Panels → Devices → Add device → Other → Virtual Device**.
2. בלשונית **Labels** של ה-VD, הוסף 3 תוויות עם ה-ID-ים: `lblStatus`,
   `lblEnv`, `lblUpdated` (את `lblEnv` אפשר לדלג אם אין לך חיישני
   אור/חום/לחות).
3. בלשונית **Main Loop**, הדבק את תוכן הקובץ, וקבע אינטרוול הרצה (מומלץ 2000
   מ"ש = כל 2 שניות).
4. שמור. ה-VD יתחיל להציג את מצב התנועה (ואם הוגדר — גם אור/חום/לחות) תוך
   כמה שניות, בלי כל תלות בגשר מעבר לכך שהוא כבר רץ ומעדכן את המשתנים.

## הרצה

```bash
npm install
npm run dev     # פיתוח/בדיקה, עם לוגים חיים
npm start       # הרצה רגילה
```

להרצה קבועה ברקע (למשל על אותה מכונה שמריצה את `server.js`), מומלץ להשתמש ב-
[PM2](https://pm2.keymetrics.io/) או ב-Task Scheduler של Windows כדי שהתהליך
יעלה אוטומטית עם המחשב.

## בדיקת תקינות

- אם `config.json` חסר או לא שלם — התהליך ייכשל עם הודעת שגיאה ברורה שאומרת
  איזה שדה חסר.
- לוגים בפורמט `[tuya] ...` — סטטוס חיבור לחיישן.
- לוגים בפורמט `[hub] ... motion DETECTED/cleared` — שינוי מצב תנועה שזוהה.
- שגיאת `Fibaro update failed` — כתובת/משתמש/סיסמה של Fibaro שגויים, או
  שהמשתמש חסר הרשאת API.
